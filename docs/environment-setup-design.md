# 采集环境准备设计

入口采用标准库实现，未安装 NumPy/PyYAML/vLLM 时也能通过源码脚本运行。
检测不修改环境、不启动服务、不访问 GPU；安装后验证才显式访问 GPU。

流程：检测目标解释器 → 显示版本、依赖、基础文件匹配 → 选择已有或新建
环境（推荐新建）→ 展示全部安装命令 → 用户确认 → 安装 → GPU/扩展验证 →
创建独立补丁包 → 生成配置、诊断报告和加载脚本。不自动启动模型服务。

- `--detect` 只读，`--dry-run` 只展示计划，自动化安装需显式 `--yes`。
- 交互默认新环境；缺少 vLLM、版本不支持或已有依赖不满足时不升级现有环境。
- 已有模式仅安装工具，使用 --no-deps/--no-build-isolation，不升级依赖。
- 新建模式用 Conda 创建新名称，拒绝 base/root 或已存在的环境名。失败停止，
  不继续后续命令，不自动删除部分创建的环境，避免误删用户数据。
- 安装限定二进制 wheels；无合适 wheel 时失败，不自动源码编译。
- 安装后核对实际版本、pip check、CUDA 张量计算和对应 native 扩展。
- 0.10.1 / 0.29.0 分别使用版本化目标文件摘要和补丁；安装成功不代表补丁
  兼容，源码不匹配则拒绝适配。已修改源码不覆盖。
- 结果写到新的专用目录，加载脚本只设置当前 shell 的临时包和采集配置。
  配置显式使用用户输出目录，不沿用维护者机器的旧默认路径。
- 专用 Conda 环境仅隔离软件依赖，不能隔离 GPU、端口或生产进程；不停止
  已有服务，后续启动需用户检查资源并确认模型。

测试分层：单元测试覆盖检测分类、确认/取消、碰撞与命令构造；替换命令执行器
模拟完整安装与失败流程；真实现有环境只读检测/GPU探测；临时目录验证隔离
补丁和实际导入，缺少 NumPy/vLLM 的基础环境验证标准库入口。
大规模依赖下载结果单独标记，不冒充已安装验收。
