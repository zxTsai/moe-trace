### 2026-11-04：动态 K MTP 采集

主要提交：`5f8a937` 设计，`aad5a0e` 实现，`28dc528` 验证与指南。

- 从配置读取最大 K，从每次实际 proposer 调用读取本轮 K，允许 0 到配置上限。
- 接入首次上下文 forward 和后续每次自回归 forward，单个物理 MTP 层可重复执行 K 次。
- 主模型普通 Decode、主模型验证和 MTP 输入路由分开保存，保留引擎、执行、请求、
  位置、候选 round/node、层号和 logical expert ID。
- 记录候选 producer 与实际验证输入；读取 sampler 输出的接受前缀。
  明确区分 accepted、首个 rejected、后续 not_adopted、未调度验证的 unverified。
- 保留全部已执行路由，不因候选未采用而删除计算；主模型、MTP 和合计分别计数。
- 导出 JSON 明细、含零负载专家的计数 CSV、按执行轮次 CSV。
- 支持 `--num-speculative-tokens K`，CPU 复验支持 `--k K`。

验证：MTP 相关 **35 项通过**，全仓库 **350 passed，无跳过**。
执行了固定源码 Python 循环的 K=1/2/3/7、接受前缀、裁短验证和失败用例；
模型/路由/采样算子和通信使用 mock，**A3/NPU 与完整 PD 服务未验收**。
证据与复现命令见[CPU 验证报告](validation/DeepSeekV4的MTP采集CPU验证.md)。

使用变化：P/D 启动命令分别指定 `--num-speculative-tokens K`，两侧保持一致；
更新到此补丁后需要重新 stage，不能沿用旧源码副本。`candidate_accepted:false` 表示
未接受；需要具体原因时读取 `candidate_decision`，不能将 not_adopted 都称为独立拒绝。

## 当前支持边界

| 项目 | 支持范围 |
| --- | --- |
| 模型 | 文本 DeepSeek V4 W8A8，单物理 MTP 层 |
| 部署 | 两机 A3，P DP4/TP4、D DP16/TP1，EP，MooncakeHybridConnector |
| 执行 | V1、同步 eager；D 无图、异步、FlashComm、多流、EPLB |
| 采集 | 仅 D 的有效 Decode/验证/MTP 输入，logical expert choices |
| 请求标识 | D 内部命名空间，尚未与 P/proxy 全局 ID 关联 |
| 存储 | D host 挂载目录，16 worker 独立保存，本地汇总，无自动上传 |
| 不包含 | 通用并行策略、PP/CP、DSpark、多模态、物理设备利用率、KV 流量 |
| 验收 | CPU 已验证；镜像构建、真实 A3/PD 和独立 NPU 路由对照待完成 |

关键框架源码必须通过版本化摘要检查；只有版本号相似、模型能启动或安装 pip 成功
都不能代替兼容性检查。`npu_verified:false` 为当前保留的验收状态标记。
